# Eval-Driven Curation: Novel Metaphor Candidates (2026-03-16)

## Source Description

These 18 metaphor candidates were surfaced by the Metaphorex eval pipeline
(Suite D, 2026-03-16). The pipeline works as follows:

1. Claude (subject model: claude-sonnet-4) analyzes five software
   engineering scenarios and identifies metaphors
2. Claude Opus (judge model) flags candidates not already in the catalog
3. A consolidation pass deduplicates and filters
4. A human curator reviews and checks off candidates worth adding

All 18 candidates in issue #1547 have been checked off by the curator,
meaning all are approved for mining.

## Access Method

**Archive URL:** https://github.com/metaphorex/metaphorex/issues/1547

The issue body itself is the structured archive. It was machine-generated
by `bun run scripts/eval.ts --suite d --create-issue` and contains a
canonical, deduplicated candidate list organized by scenario. No external
scraping script is needed -- the eval pipeline already produced the

To re-extract candidates from the issue body, use the GitHub API:

```bash
gh issue view 1547 --repo metaphorex/metaphorex --json body
```

The issue body uses a consistent markdown format: each candidate is a
checkbox item with slug, name, source domain, description, scenario, and
generation source (raw, m4x, or both).

## Extraction Strategy

Each candidate becomes a standard catalog entry of kind `metaphor`. The
issue body provides:

- **slug** -- kebab-case identifier (use as-is)
- **name** -- title case name (issue uses title case already)
- **source domain** -- maps to `source_frame` in the schema
- **description** -- brief summary for the Miner to expand
- **scenario** -- the eval scenario that surfaced it (for provenance)
- **generated by** -- whether raw Claude, m4x-augmented, or both found it

The Miner must research each metaphor independently, using web sources and
prior art. The eval-generated description is a starting point, not the
final word. Per curator instruction: "Agents should make sure to scour the
web for prior art and references, especially for creating the transfers
and limits sections for each."

## Gotchas

1. **Source frame precision** -- The surveyor flagged several source frame
   choices in the v1 manifest. This v2 manifest uses the following
   corrections:
   - `organizational-memory-is-archaeological-layers`: `geology` (not
     `exploration` -- stratified layers are a geological concept)
   - `microservices-are-city-districts`: `governance` (retained -- the
     metaphor emphasizes local governance and jurisdiction; urban-planning
     does not exist as a frame)
   - `audit-trails-are-forensic-footprints`: `surveillance` (retained --
     forensics does not exist as a frame; surveillance covers the
     observation and evidence-gathering aspects)
   - `scaling-is-dilution`: `fluid-dynamics` (retained -- chemistry does
     not exist as a frame; dilution is a fluid dynamics concept)

2. **production-data-is-food truncation** -- The issue body appears
   truncated after the last candidate. The description in the manifest is
   reconstructed from the partial text and the candidate name.

3. **No sub-issue cap concern** -- 18 candidates is well under the GitHub
   100 sub-issue limit.

4. **Re-prospecting context** -- This is a v2 playbook replacing the
   rejected PR #1709. The v1 manifest had: invalid `kind` value
   (`conceptual-metaphor` instead of `metaphor`), ALL-CAPS names instead
   of title case, and several imprecise source frame mappings. All issues
   are corrected in this version.
